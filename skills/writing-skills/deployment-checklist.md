# Skill Deployment Checklist

Read this immediately before declaring a new or modified skill ready.

## Evidence

- [ ] Baseline/control captured before guidance changes
- [ ] Concrete failures and rationalizations recorded
- [ ] Guidance tested against the same scenarios
- [ ] Behavior-shaping wording micro-tested with 5+ fresh-context repetitions
- [ ] New loopholes refined and re-tested

## Structure and Discovery

- [ ] Name uses letters, numbers, and hyphens
- [ ] Frontmatter has `name` and trigger-only `description`
- [ ] Description starts with “Use when...” and uses third person
- [ ] Searchable symptoms, errors, tools, and synonyms appear early
- [ ] Overview states the core principle
- [ ] Main `SKILL.md` is concise; heavy detail is linked progressively
- [ ] Code is inline only when short, otherwise linked
- [ ] At most one strong example

## Quality

- [ ] Guidance form matches the observed failure
- [ ] Flowchart exists only for a non-obvious decision
- [ ] Quick reference and common mistakes are present when useful
- [ ] No narrative history or repeated cross-skill instructions
- [ ] Supporting files are referenced and necessary
- [ ] Relevant automated/static checks pass

Do not create or commit multiple unvalidated skills as a batch.
